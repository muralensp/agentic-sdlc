Build a throwaway to answer one design question. It is never merged.

1. Write the question the prototype must answer and what result would settle it.
2. Work on a spike/ branch. Keep it small and cheap; skip tests, polish and error handling that do not help answer the question.
3. Run it and observe the actual behaviour.
4. Record the answer, and what surprised you, in the brief or in docs/research/.
5. Do not carry prototype code into production code. The branch is deleted after the answer is recorded.
